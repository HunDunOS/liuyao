  六爻 × 混沌 HunDunOS —— 接手指南
  2026-10-11
════════════════════════════════════════════════════════════════════

  你手上这个包，是一个【从引导扇区开始、全部自己写的操作系统】，
  外加它自己那门语言（六爻）。这份指南是"照着走就能造出来"。

  全流程大概 3 分钟。中间不需要联网（除了装编译器）。


────────────────────────────────────────────────────────────────────
  〇、先说清楚：这东西是什么
────────────────────────────────────────────────────────────────────

  一个操作系统 + 一门语言。特色三条：

    ① 源码里【只有字母和数字】—— 一个标点都不打
       词用六爻（64 条指令，小写两字母）  tt 定义函数  nn 循环  nr 条件
       类型用五行（大写）                J 金 M 木 S 水 H 火 T 土
       符号用数字（两位）                01 (  02 )  08 {  09 }

    ② 【抛弃汇编】：源码直接出机器码，不经过 as，不经过 ld
       编译器自带一个 x86-64 指令编码器

    ③ 【自举】：编译器自己就是用六爻写的
       stage1 编它自己 → 产物和 C 写的 stage0 逐字节一样

  设计出发点（一句话）：
      Windows 一切皆注册表 / Unix 一切皆文件 / 混沌 一切皆哈希


────────────────────────────────────────────────────────────────────
  一、你要装什么
────────────────────────────────────────────────────────────────────

  ▍必要（两个）
      一个 C 编译器（cc / gcc / clang 都行）
      python3

  ▍可选（想看见图形/跑真机才要）
      qemu-system-i386      ← 启动图形版 ISO
      qemu-system-x86_64    ← 启动 64 位版
      qemu-x86_64           ← 在 arm 机器上跑 x86-64 程序

  各平台怎么装：

  Linux（Debian/Ubuntu）
      sudo apt install gcc python3 qemu-system-x86 qemu-user

  Linux（Arch）
      sudo pacman -S gcc python qemu-system-x86 qemu-user

  macOS
      xcode-select --install              # 自带 clang
      brew install qemu                   # 可选

  Windows
      装 Git for Windows，从 Git Bash 里跑 sh 编.sh …
      或者装 MSYS2，在里面 pkg 装 gcc python3

  Android（Termux）
      pkg update
      pkg install clang python qemu-user-x86-64
      ★ Termux 的 sh 是 busybox ash，不认中文函数名/变量名 —— 脚本里已经回避了


────────────────────────────────────────────────────────────────────
  二、第一步：把语言跑起来（1 分钟）
────────────────────────────────────────────────────────────────────

  cd 六爻工具链
  sh 编.sh 示例/你好.ly

  应该出：

      [1/3] 编编译器（cc）
      [2/3] 编源码 → 可重定位对象
      [3/3] 链接（不用 as、不用 ld）
      ── 跑 ──
      你好，六爻

  ★ 这一步成功，说明【源码 → 字节 → 可执行】这条链在你机器上是通的。
    x86-64 电脑原生跑；arm 机器（手机/苹果 M 芯片）会自动用 qemu-x86_64。


────────────────────────────────────────────────────────────────────
  三、第二步：验证自举（2 分钟）
────────────────────────────────────────────────────────────────────

  cd 源码
  sh 构建/编译.sh 自举

  应该出：

      ── ★ 自己编自己：stage1 编译它自己 ──
      编译器            ★ 19607 行 .s 逐字节一致
      ──────────────────────────────────
      一致 1 / 不同 0 / 失败 0

  ★ 这一步的意思是：
      用 C 写的编译器（stage0）和用六爻写的编译器（stage1）
      编同一份「编译器源码」，吐出的汇编【逐字节一样】。
      语言从此能自己描述自己 —— 这就是"自举成立"。

  ⏱ 这一步要多久，看你机器：
      x86-64 电脑原生跑        30 秒左右
      手机（arm）/ 苹果 M 芯片  慢很多 —— 要先用 qemu 把 stage1 跑起来，
                               而 stage1 要吐 19607 行汇编。可能要好几分钟。
      等不及就跳过这一步，直接做第三步（那个快）。


────────────────────────────────────────────────────────────────────
  四、第三步：把整个系统编出来
────────────────────────────────────────────────────────────────────

  cd 源码

  # 四个模块级对拍（换词不改语义的证据链）
  sh 构建/编译.sh 词法      # 六爻源码 vs 旧拼音源码，词法流逐行一致
  sh 构建/编译.sh 语法      # 符号表逐行一致
  sh 构建/编译.sh 出码      # .s 逐字节一致
  sh 工具/对拍字节.sh       # 机器码与 GNU as 逐字节一致

  # 整个系统：九个模块 → 一个可执行
  sh 构建/编译.sh 整系统
  ./构建/中间/整系统/系统

  应该出：

      [盘] 主通道没有 ATA 盘
      [HDGX] 没有盘
      [压] 原文 110 字节
      [压] 压缩后 26 字节
      [压] 解出 110 字节
      [压] 逐字节一致 ✓


────────────────────────────────────────────────────────────────────
  五、第四步（可选）：造一个能开机的 ISO
────────────────────────────────────────────────────────────────────

  cd 源码
  sh 构建/构建64.sh                    # 出 混沌64.iso
  qemu-system-x86_64 -cdrom 混沌64.iso -m 256 -vga std

  屏幕上应该出现：

      混沌 HunDunOS  —  x86-64 长模式

  ★ 中文在文本模式下显示不出来（VGA 文本字库没有汉字），
    英文数字是正常的。看中文请加 -serial stdio 看串口。

  想只看串口（不弹窗口）：

      qemu-system-x86_64 -cdrom 混沌64.iso -m 256 \
          -display none -serial stdio


────────────────────────────────────────────────────────────────────
  六、一句话地图：源码里都有什么
────────────────────────────────────────────────────────────────────

  六爻工具链/
    编.sh              一键：源码 → 可执行
    编译器/
      lyc.c            C 写的编译器（stage0）—— 只用来造出 stage1
      编码器.c         x86-64 指令编码器（约 700 行）
      词法.ly          用六爻写的词法分析器
      语法.ly          用六爻写的符号表扫描
      出码.ly          用六爻写的出码器
      编译器.ly        上面三个拼起来 = stage1 的完整源码
    工具/
      符号.py          数字标点 → 标点
      小链接.py        可重定位对象 + 运行时 → 可执行
    宿主/
      宿主64.s         跑在操作系统上的运行时（打印/读键的桩）
      预造/            造好的运行时 —— 手机上没 x86-64 汇编器也能用

  源码/
    模块/            九个模块：盘 盘格式 压缩 机器 包 壳 编辑器 桌面 主终端
    引导器/          boot1.asm（16 位）+ boot2_64.asm（进长模式）
    运行时/          原语64.s（裸机运行时，还很薄）
    工具/            拆分.py 造字.py xelf.py xiso.py 小链接.py 对拍*.py
    文档/            设计文档、自举路线图、六爻表
    构建/            构建.sh（32位老路）/ 构建64.sh / 编译.sh（阶梯菜单）

────────────────────────────────────────────────────────────────────
  八、卡住了怎么办
────────────────────────────────────────────────────────────────────

  · 编.sh 报 "找不到 C 编译器"     → 装 gcc 或 clang
  · 跑不起来、说 Exec format error  → 那是 arm 机器，装 qemu-user
  · 报 "名字不存在：xxx"            → 那个词不是关键字，查 文档/六爻表_定稿.txt
  · 报 "期望 '('"                   → 括号没打（数字标点里 01 是 (  02 是 )）
  · 名字太长                        → 编译器给名字留 900 字节（约 100 个汉字）
  · 挂载盘/网盘上跑不了（Permission denied）
                                    → 那是 noexec 盘，解压到自己的家目录再跑

  编译器的报错都带行号，先看行号那一行。

  ★ 一条纪律（作者定的，跟着做）：
       改完必须跑一次。"我觉得改好了"不算。
